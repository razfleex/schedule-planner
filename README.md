# Программа для планирования учебных занятий и расписаний

## 1. Общие сведения

### 1.1 Основание для разработки

Проект разрабатывается в рамках лабораторных работ по дисциплине «Программная инженерия». В качестве темы проекта выбрана «Программа для планирования учебных занятий и расписаний».

### 1.2 Наименование проекта

Полное наименование проекта: «Программа для планирования учебных занятий и расписаний».

### 1.3 Цель разработки

Целью проекта является разработка веб-приложения для создания, редактирования и просмотра расписания учебных занятий.

Программа должна упростить процесс составления расписания за счёт хранения информации о преподавателях, учебных группах, дисциплинах и аудиториях, а также автоматической проверки создаваемых занятий на наличие временных конфликтов.

### 1.4 Состав работ

В рамках проекта планируется:

- определить и формализовать требования к программному обеспечению;
- спроектировать структуру и архитектуру программы;
- реализовать основные сущности предметной области средствами Python с применением принципов объектно-ориентированного программирования и SOLID;
- спроектировать и реализовать базу данных;
- реализовать серверную часть и программный интерфейс с использованием FastAPI;
- создать минимальный пользовательский интерфейс;
- реализовать автоматизированные тесты;
- разработать и документировать REST API.

## 2. Назначение программы

Программа предназначена для составления и ведения расписания учебных занятий.

Основным пользователем системы является сотрудник, ответственный за формирование учебного расписания. Пользователь должен иметь возможность работать с данными о преподавателях, учебных группах, дисциплинах и аудиториях, а также создавать на их основе учебные занятия.

Программа должна обеспечивать:

- хранение и изменение информации о преподавателях;
- хранение и изменение информации об учебных группах;
- хранение и изменение информации о дисциплинах;
- хранение и изменение информации об аудиториях;
- создание, редактирование и удаление учебных занятий;
- просмотр сформированного расписания;
- фильтрацию расписания по основным параметрам;
- автоматическую проверку создаваемых и изменяемых занятий на наличие временных конфликтов.

В рамках основной версии проекта расписание формируется для типовой учебной недели. Автоматическая генерация оптимального расписания не входит в основную функциональность программы.

## 3. Описание программы

### 3.1 Общая схема работы

Программа представляет собой веб-приложение для ручного формирования учебного расписания.

Пользователь работает с основными данными системы: преподавателями, учебными группами, дисциплинами и аудиториями. На основе этих данных создаются учебные занятия, из которых формируется расписание.

При создании или изменении занятия программа должна проверять, не возникает ли временного конфликта с уже существующими занятиями.

### 3.2 Основные сущности системы

В программе используются следующие основные сущности:

- **Преподаватель** — содержит информацию о преподавателе, который проводит учебное занятие;
- **Учебная группа** — содержит информацию о группе студентов, для которой проводится занятие;
- **Дисциплина** — содержит информацию об учебном предмете;
- **Аудитория** — содержит информацию о помещении, в котором проводится занятие;
- **Занятие** — связывает преподавателя, учебную группу, дисциплину и аудиторию, а также содержит информацию о дне недели и времени проведения занятия.

В основной версии программы одно занятие связано с одним преподавателем, одной учебной группой, одной дисциплиной и одной аудиторией.

### 3.3 Формирование расписания

Расписание формируется для типовой учебной недели.

Для каждого занятия указываются:

- дисциплина;
- преподаватель;
- учебная группа;
- аудитория;
- день недели;
- время начала занятия;
- время окончания занятия.

Пользователь должен иметь возможность создавать новые занятия, изменять существующие и удалять их.

Перед сохранением занятия программа должна проверить наличие временных конфликтов.

Конфликт возникает, если в пересекающееся время:

- выбранный преподаватель уже проводит другое занятие;
- выбранная учебная группа уже находится на другом занятии;
- выбранная аудитория уже занята другим занятием.

При обнаружении конфликта занятие не должно быть сохранено, а пользователю должна быть показана информация о причине конфликта.

### 3.4 Просмотр расписания

Пользователь должен иметь возможность просматривать сформированное расписание.

Для удобства работы должна быть предусмотрена фильтрация расписания:

- по учебной группе;
- по преподавателю;
- по аудитории;
- по дню недели.

### 3.5 Основные сценарии использования

#### 3.5.1 Добавление данных для составления расписания

Пользователь добавляет в систему данные о преподавателях, учебных группах, дисциплинах и аудиториях. После этого данные могут использоваться при создании учебных занятий.

#### 3.5.2 Создание учебного занятия

Пользователь выбирает дисциплину, преподавателя, учебную группу и аудиторию, после чего указывает день недели и время проведения занятия.

Программа проверяет введённые данные и наличие временных конфликтов.

Если конфликтов нет, занятие сохраняется и отображается в расписании.

Если обнаружен конфликт, программа сообщает пользователю его причину и не сохраняет занятие.

#### 3.5.3 Изменение учебного занятия

Пользователь выбирает существующее занятие и изменяет необходимые данные.

Перед сохранением изменений программа повторно выполняет проверку временных конфликтов.

#### 3.5.4 Удаление учебного занятия

Пользователь выбирает существующее занятие и удаляет его из расписания.

#### 3.5.5 Просмотр расписания

Пользователь открывает расписание и при необходимости применяет фильтры для просмотра занятий по выбранной группе, преподавателю, аудитории или дню недели.

### 3.6 Ограничения основной версии

В основную версию программы не входят:

- автоматическая генерация оптимального расписания;
- разделение учебной недели на числитель и знаменатель;
- работа с расписанием по конкретным календарным датам;
- учёт посещаемости и успеваемости студентов;
- отправка уведомлений;
- мобильное приложение;
- интеграция с внешними информационными системами образовательной организации;
- сложная система пользовательских ролей и прав доступа.

Перечисленные возможности могут быть рассмотрены как дальнейшее развитие проекта после реализации основной функциональности.

## 4. Требования к системе

### 4.1 Функциональные требования

Программа должна предоставлять пользователю следующие возможности.

#### 4.1.1 Управление преподавателями

Пользователь должен иметь возможность:

- добавлять преподавателей;
- просматривать список преподавателей;
- изменять данные преподавателей;
- удалять преподавателей.

#### 4.1.2 Управление учебными группами

Пользователь должен иметь возможность:

- добавлять учебные группы;
- просматривать список учебных групп;
- изменять данные учебных групп;
- удалять учебные группы.

#### 4.1.3 Управление дисциплинами

Пользователь должен иметь возможность:

- добавлять дисциплины;
- просматривать список дисциплин;
- изменять данные дисциплин;
- удалять дисциплины.

#### 4.1.4 Управление аудиториями

Пользователь должен иметь возможность:

- добавлять аудитории;
- просматривать список аудиторий;
- изменять данные аудиторий;
- удалять аудитории.

#### 4.1.5 Управление учебными занятиями

Пользователь должен иметь возможность:

- создавать новое учебное занятие;
- просматривать информацию о существующем занятии;
- изменять данные занятия;
- удалять занятие.

Для создания занятия должны быть указаны:

- дисциплина;
- преподаватель;
- учебная группа;
- аудитория;
- день недели;
- время начала;
- время окончания.

#### 4.1.6 Проверка временных конфликтов

При создании или изменении учебного занятия программа должна проверять его на пересечение с существующими занятиями.

Временные интервалы занятий считаются конфликтующими, если они хотя бы частично пересекаются. Если время окончания одного занятия совпадает со временем начала другого занятия, такие занятия конфликтующими не считаются.

Программа не должна разрешать сохранение занятия, если в пересекающееся время:

- преподаватель уже назначен на другое занятие;
- учебная группа уже назначена на другое занятие;
- аудитория уже используется для другого занятия.

При обнаружении конфликта пользователь должен получить сообщение с указанием причины, по которой занятие не может быть сохранено.

#### 4.1.7 Просмотр расписания

Программа должна обеспечивать просмотр сформированного расписания.

Пользователь должен иметь возможность фильтровать занятия:

- по учебной группе;
- по преподавателю;
- по аудитории;
- по дню недели.

### 4.2 Нефункциональные требования

#### 4.2.1 Требования к корректности данных

Программа должна проверять вводимые пользователем данные перед их сохранением.

Не должны сохраняться данные, необходимые поля которых не заполнены или содержат недопустимые значения.

Время окончания занятия должно быть позже времени его начала.

#### 4.2.2 Требования к пользовательскому интерфейсу

Пользовательский интерфейс должен обеспечивать доступ к основным функциям программы через веб-браузер.

Пользователю должны выводиться понятные сообщения при некорректном вводе данных или возникновении конфликтов расписания.

#### 4.2.3 Требования к сохранению данных

Созданные пользователем данные о преподавателях, учебных группах, дисциплинах, аудиториях и занятиях должны сохраняться и быть доступны при последующей работе с программой.

#### 4.2.4 Требования к структуре программного обеспечения

Программное обеспечение должно иметь структуру, позволяющую разделять основные части системы и независимо развивать их в ходе последующих лабораторных работ.

Изменение одной части программы по возможности не должно требовать внесения несвязанных изменений в остальные части системы.

#### 4.2.5 Требования к тестируемости

Основная функциональность программы должна допускать автоматизированную проверку.

Особое внимание при тестировании должно уделяться:

- созданию и изменению основных сущностей;
- проверке корректности входных данных;
- обнаружению конфликтов расписания;
- пограничным случаям пересечения времени занятий.

### 4.3 Ограничения системы

В основной версии программы:

- расписание составляется вручную пользователем;
- расписание формируется для типовой учебной недели;
- одно занятие связано с одним преподавателем, одной учебной группой, одной дисциплиной и одной аудиторией;
- автоматическая генерация и оптимизация расписания не выполняются;
- сложное разделение прав пользователей не предусматривается.
